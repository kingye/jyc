fix: never split a lesson between the prompt and the archive (#971)

## Why

The review of #971 came back APPROVE with two things to fix, and CI
came back with a third — the schema budget, where my arithmetic was
wrong, not the code:

- **The budget.** CI measured 9,451 against a 9,400 ceiling. The cause
  was my own measurement: a Rust string continuation (a backslash at
  the end of a line) drops the newline *and* the indentation after it,
  and I counted the indentation. The real figures are 9,183 for the
  other tools and 156 / 88 for the two new ones.
- **That mistake had a cost.** To squeeze the two descriptions into the
  old ceiling I had cut the one sentence that says *why* the tool is
  worth calling — that a recorded lesson rides in the next turn's
  prompt. The budget is a test constant; raising it costs no prompt
  byte, while the description is prompt text the model reads. The
  ceiling is now 9,600, raised on purpose, and the description keeps
  its motivation.
- **A lesson could be cut in half.** The split between "in the prompt"
  and "in the archive" landed on a byte boundary, so a lesson long
  enough to straddle it was a head in one end and a tail in the other
  — and the count in the note said the same lesson was both shown and
  not shown.

## What

- **The cut lands on a line boundary.** The split moves *back* to the
  start of the line it landed in, so a lesson is whole in one end or
  the other and never half a rule in each. Only a line longer than
  twice the cap keeps the byte cut — there the fragment is marked with
  an ellipsis and the note says the rule is cut in two. The counts are
  now exact: the lessons of the file are the ones in the prompt plus
  the ones in the archive, whichever end they are in.
- **`lesson_read` no longer lies about a broken file.** A read failure
  other than "no file yet" is reported as an error, like `lesson_add`
  reports it. Before, the read answered "no lessons recorded yet" and
  the add answered "could not read" — the model would have been told
  to record a lesson into a file it cannot read.
- **The prune note is executable.** It says the file should be pruned;
  it now says to ask the *user*, who is the only one who can.
- **Smaller things from the review**: `lesson_read` says that a file
  which fits entirely is already in the prompt; it answers a bad path
  as a tool error rather than a bare `Err`; `sync_all` replaces the
  no-op `flush`, so the line is on disk; and the tests that could not
  fail now fail — the archive cap asserts the real bound, and the two
  ends assert that neither repeats the other's lines.
- **AGENTS.md**: a house rule for the mistake I made in this PR — a
  new subagent is spawned with `jyc_spawn_subagent` (and a `type`),
  never by sending `jyc_send_to_topic` to a name nobody owns: that
  creates a plain agent, with its own identity and no role's
  constraints.

## Validation

- Local: `cargo fmt -- --check`, `cargo check -p jyc-agent --tests` (compile-only; the suite runs in CI).
- New tests: `read_reports_an_unreadable_file_instead_of_an_empty_one`,
  `prompt_section_shows_a_long_lesson_whole`,
  `prompt_section_marks_a_lesson_too_long_to_carry`,
  `no_lesson_is_split_between_the_two_ends`, and a stronger
  `the_prompt_and_the_read_agree_on_the_split`.
